# Native parity inventory: Planned payments

> [!abstract] Scope
> Routes: `/planned`. Source: `apps/frontend/src/pages/PlannedPaymentsPage.tsx`, `apps/frontend/src/features/planned/`, plus the shared `VirtualDataTable`, `ColumnFilter`, `RowMenu`, `DatePicker`, combobox and `TagInput` components as they are used here. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/204-vision-native-swift-app-target|ADR-204]].

## Screens

### `/planned` — Planned

Component: `apps/frontend/src/pages/PlannedPaymentsPage.tsx`. Feature doc: [[docs/features/plannedTransactions|Planned Transactions]]. Design intent: [[docs/adr/183-remaining-screens-redesign|ADR-183]].

Page title `plannedPage.title` "Planned", subtitle `plannedPage.subtitle` "See recurring bills and future payments before they land", icon `CalendarClock` (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:310`). Sidebar entry `nav.plannedPayments` "Planned Payments" with the live `planned-due` badge (`apps/frontend/src/lib/navigation.ts:79`).

There is no calendar or month view on this route. The only date-laid-out view is the eight-day strip below; everything else is the table.

**Regions shown:**

- Loading state: header plus a skeleton card with eight day tiles and a skeleton table (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:236`).
- Error state: `PageError` with title `common.error` "Couldn't load this page", the error message and a Retry button (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:271`, `apps/frontend/src/components/shared/PageError.tsx:15`).
- **Next 7 days strip** (`NextSevenDaysStrip`): heading `plannedPage.next7.title` "Next 7 days" (`apps/frontend/src/features/planned/NextSevenDaysStrip.tsx:110`); due count `plannedPage.next7.dueCount` "{count} payment(s) due" (plural, `:115`); signed window total converted to the default currency, shown only when the count is above zero, with a skeleton while FX rates load (`:117`); date range `plannedPage.next7.range` "{from} - {to}" in the app date format (`:91`); FX-omission warning `plannedPage.fxUnavailable` "{count} payment(s) left out: exchange rate(s) unavailable" (`:154`).
  - Side figure `plannedPage.estMonthly` "Estimated monthly": signed net monthly impact of active recurring rows, converted to the default currency, with its own skeleton and FX-omission warning (`:170`, `:195`). Multipliers: daily ×30, weekly ×4.33, biweekly ×2.17, monthly ×1, quarterly ×1/3, yearly ×1/12, custom ×30/interval (`apps/frontend/src/features/planned/plannedCurrencyTotals.ts:48`). The sum uses all loaded payments, active and recurring only (`:66`).
  - Eight day tiles, today through today+7; today is labelled `plannedPage.next7.today` "Today" and highlighted, other tiles show a localized short weekday and day number (`apps/frontend/src/features/planned/NextSevenDaysStrip.tsx:211`). Only active payments with a parseable due date in the window are placed; each day sorts largest outflow first (`apps/frontend/src/features/planned/nextSevenDays.ts:41`).
  - Each tile shows at most two items (name, signed amount in the payment currency, check icon and strikethrough when executed), then `plannedPage.next7.more` "+{n} more" (`apps/frontend/src/features/planned/NextSevenDaysStrip.tsx:214`, `:307`). An empty tile shows a dot.
  - When nothing is due: `plannedPage.next7.emptyTitle` "Nothing due in the next 7 days" / `plannedPage.next7.emptyDesc` (`:319`).
- **Match suggestions banner** (`MatchSuggestionsBanner`), hidden when there are no suggestions: `plannedPage.suggestions.title` "{count} likely match(es)" and `plannedPage.suggestions.subtitle` (`apps/frontend/src/features/planned/MatchSuggestionsBanner.tsx:39`). Data: `GET /api/planned-transactions/match-suggestions`.
- **Recurring detection panel** (`RecurringDetectionPanel`). Data: `GET /api/info/recurring-patterns`. It renders nothing until dismissals have loaded and nothing on fetch error (`apps/frontend/src/features/planned/RecurringDetectionPanel.tsx:230`, `:253`).
  - Loading card `recurring.loading` "Looking for recurring payments" (`:234`).
  - Caught-up status line `recurring.allCaughtUp` "All caught up" + `recurring.noPatterns` (`:255`).
  - Amount-change card `recurring.amountChanges` "Amounts that changed" with a count badge; collapsed by default; when open, `recurring.amountChangesDesc` and up to five rows: payee, previous amount struck through, new amount (red if increased, green if decreased), signed percent badge, `recurring.changedOn` "Changed on {date}" (`:271`, `:329`).
  - Pattern card `recurring.patterns` "Recurring payments found" with a count badge; collapsed by default; when open, `recurring.patternsDesc` and one row per pattern: payee, confidence badge "{n}% High/Medium/Low" (≥80 high, ≥60 medium; `:590`), pattern badge `recurring.pattern.*`, category name, "· {n} `recurring.seen`", `recurring.nextExpected` "Next expected: {date}", latest amount (`:437`). Patterns already planned or dismissed are hidden (`:222`).
- **Payments table** (`PlannedPaymentsTable` on `VirtualDataTable`): title `plannedPage.tableTitle` "All payments", subtitle `plannedPage.tableSubtitle` "{n} planned payments" (n = all loaded rows, not the filtered count) (`apps/frontend/src/features/planned/PlannedPaymentsTable.tsx:356`). Columns:
  - `plannedPage.col.payment` "Payment": name (struck through when paused or executed), `plannedPage.loanBadge` "Loan" badge, `plannedPage.statusPaused` "Paused" badge, external-link icon when the row has a safe URL, "→ payee" sub-line (`:86`).
  - `plannedPage.col.amount` "Amount": signed amount in the row currency, green when positive (`:142`).
  - `plannedPage.col.dueDate` "Due date": `PlannedDueBadge` showing `plannedPage.due.noDate` "No date", `plannedPage.due.invalid` "Invalid date", `plannedPage.due.today` "Today", `plannedPage.due.overdue` "Overdue", `plannedPage.due.tomorrow` "Tomorrow", `plannedPage.due.inDays` "In {n} days" (2–7), else the formatted date (`apps/frontend/src/features/planned/PlannedDueBadge.tsx:16`).
  - `plannedPage.col.recurrence` "Recurrence": loans show `plannedPage.loanTerm` "Loan ({count} month(s))"; recurring rows show `plannedPage.freq.*` or `plannedPage.everyNDays` "Every {n} days" for custom; one-time rows show `plannedPage.oneTime` "One-time"; plus `plannedPage.executedCount` "Paid {n} times" when the execution count is above zero (`apps/frontend/src/features/planned/PlannedPaymentsTable.tsx:174`).
  - `plannedPage.col.category` "Category": outlined badge or "—" (`:236`).
  - Unlabelled status column: the Mark as paid button, or the success badge `plannedPage.execute.linked` "Paid (transaction {n})" (`:255`).
  - Unlabelled actions column: row ••• menu (`:294`).
- Empty states inside the table: no payments at all → `plannedPage.empty` "Nothing planned yet" / `plannedPage.emptyDesc` with an Add payment action; payments exist but the active-only view hides them all → `plannedPage.emptyFiltered` "No active payments" / `plannedPage.emptyFilteredDesc` with an Include paused action (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:282`).

**URL state:** `show_all` (boolean). Absent or anything other than `true` means active only; `true` includes paused payments. Written with replace, preserving other parameters, and deleted when false (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:62`, `apps/frontend/src/hooks/useSearchParamState.ts:14`, `:41`). It drives both the server query (`active: !show_all`, `limit: 1000`, `apps/frontend/src/hooks/usePlannedPayments.ts:42`) and a client-side `is_active` filter on the table (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:119`). No other route state: sheet, dialog, sort, search and column filters are component state only.

#### Sheet: New payment / Edit payment (`PlannedPaymentForm`)

Opened from: rows 5, 6, 24, 28. Source: `apps/frontend/src/features/planned/PlannedPaymentForm.tsx`. Right-hand sheet; title `plannedForm.newTitle` "New payment" or `plannedForm.editTitle` "Edit payment" (`:388`). Validation is field-level (no zod): errors appear only after a blocked submit, focus moves to the first invalid field in order name, amount, due date, bank, principal, rate, term, custom days (`:67`, `:258`). Submits `POST /api/planned-transactions` (create) or `PATCH /api/planned-transactions/:id` (edit) through the page (`apps/frontend/src/pages/PlannedPaymentsPage.tsx:206`); success toasts `plannedPage.toast.created` / `plannedPage.toast.updated`, failure `plannedPage.saveFailed` "Couldn't save the payment: {msg}", and the sheet stays open on failure.
Fields:

- Name — text input `pp-name`, label `plannedForm.nameRequired2` "Name", placeholder `plannedForm.namePlaceholder`; required, trimmed (`plannedForm.nameRequired` "Name is required") (`:421`).
- Amount — text input `pp-amount`, decimal keyboard, locale placeholder, unsigned magnitude; label `plannedForm.amountRequired2` "Amount"; required unless loan (`plannedForm.amountRequired`); parsed with the app number format; on edit shows `abs(amount)` (`:443`, `:307`).
- Currency — select `pp-currency`, label `plannedForm.currency`; options EUR, USD, GBP, CHF, CZK, PLN; default is the app default currency (`:466`).
- Direction — segmented control, label `plannedForm.direction`: `plannedForm.direction.expense` "Expense" (default) / `plannedForm.direction.income` "Income"; owns the stored sign (expense negative). - Due date — `DatePicker` `pp-due-date`, label `plannedForm.dueDate`, placeholder `plannedForm.pickDate`; required (`validation.required`); defaults to today for new payments (`:539`, `:117`).
- Payee — `RecipientCombobox` `pp-recipient`, label `plannedForm.recipient` "Payee"; optional; select-only here (no create) (`:561`).
- Category — `CategoryCombobox` `pp-category`, label `plannedForm.category`; optional (`:578`).

## Cross-cutting notes

- **Endpoints used on this route:** `GET /api/planned-transactions` (`active`, `limit=1000`), `POST /api/planned-transactions`, `PATCH /api/planned-transactions/:id` (edit, pause, resume), `DELETE /api/planned-transactions/:id`, `POST /api/planned-transactions/:id/execute`, `GET /api/planned-transactions/match-suggestions`, `GET /api/info/recurring-patterns`, `GET /api/transactions` (link candidates and history lookups), `GET`/`PUT /api/settings/dismissed_recurring_patterns`, and `GET /api/recipients/:id` via `getRecipient` for payee clusters (`apps/frontend/src/lib/api/planned.ts:16`–`:108`, `apps/frontend/src/lib/api/info.ts:90`, `apps/frontend/src/features/planned/LinkTransactionDialog.tsx:99`).
- **Mutations update the list in place** from the server response rather than refetching, and invalidate the upcoming-payments and account-planned caches that feed the sidebar badge, Home and account pages (`apps/frontend/src/hooks/usePlannedPayments.ts:52`).
- **Sign convention:** money out is negative, money in positive; the sheet stores a magnitude plus the Direction control; loans are always expense and the server owns their amount (`apps/frontend/src/features/planned/PlannedPaymentForm.tsx:51`, `:318`). Track in the recurring panel signs by the detected direction (`apps/frontend/src/features/planned/RecurringDetectionPanel.tsx:187`).
- **FX:** strip totals and Estimated monthly convert to the default currency and count, rather than blend, payments without a rate (`apps/frontend/src/features/planned/plannedCurrencyTotals.ts:25`).
- **Shared pickers** used in the sheet and link dialog: `DatePicker` (button opening a calendar popover plus a typed-date input labelled `datePicker.inputLabel` "Enter date ({format})", optional Clear), `RecipientCombobox` (search `combobox.recipient.search`), `CategoryCombobox` (`combobox.category.placeholder`), `AccountCombobox` (`combobox.account.placeholder`, emits an existing account id), `TagInput` (search, create `tags.create`, remove `aria.removeTag`). Each is portalled into the sheet. Their own internals are inventoried with the shared components, not here.
- **Recurring-dismissal persistence** is dual: localStorage key `dismissed_recurring_patterns` and the same backend setting, merged on load (`apps/frontend/src/features/planned/RecurringDetectionPanel.tsx:116`). The reset lives in Settings, outside this route.
- **Related surfaces outside this route (not inventoried here):** the dashboard upcoming-payments reminder `UpcomingPaymentsNotification` and its occurrence-keyed dismissals (`apps/frontend/src/components/notifications/UpcomingPaymentsNotification.tsx`), the Home `UpcomingPaymentsList` and `NeedsAttentionList` links to `/planned`, the sidebar `planned-due` badge, and the Electron dock/taskbar badge that `UpcomingPaymentsNotification` drives. No `window.electronAPI` call exists in this route's scope.
- **Toasts** are Sonner toasts; only Pause/Resume carries an action (Undo).
