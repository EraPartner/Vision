### `/portfolio/net-worth`: Net worth

Component: `apps/frontend/src/pages/portfolio/net-worth/NetWorthPage.tsx`. Feature doc: [[docs/features/net-worth|Net Worth]].

Native implementation: [[apps/native/Sources/VisionNativeUI/NetWorthView.swift|NetWorthView]] renders the page using [[apps/native/Sources/VisionNativeCore/Screens/Portfolio/NetWorthModel.swift|NetWorthModel]], [[apps/native/Sources/VisionNativeCore/Screens/Portfolio/NetWorthData.swift|NetWorthData]] and [[apps/native/Sources/VisionNativeCore/Screens/Portfolio/NetWorthService.swift|NetWorthService]]. ### `/portfolio/import`: Portfolio import

Component: `apps/frontend/src/pages/portfolio/PortfolioImportPage.tsx` (default export), which renders `PortfolioImportSession` and `PortfolioImportHistory`. Feature doc: [[docs/features/portfolio-import|Portfolio Import]].

> [!info] Native staging and history (phase 3j)
> `PortfolioImportView`, `PortfolioImportSessionView`, `PortfolioImportStatementView`, `PortfolioImportAdvancedView`, `PortfolioImportConfigFields`, `PortfolioImportHeadersView`, and `PortfolioImportHistoryView` render these controls in SwiftUI. `PortfolioImportSessionModel` stages statements sequentially, retains previous pending batch links when routing changes, and stops after the current statement; the advanced importer cancels its active stream. `PortfolioImportScreens` coordinates rollback and refresh across the session, parsers and history. The native implementation uses the same reviewed reconciliation and import endpoints; [[docs/api/portfolio-imports|the read-only probe]] supplies maintained-format detection and bounded CSV header/sample previews for CSV, XLS and XLSX without reproducing the TypeScript adapters in Swift.
>
> Staged metadata and review settings use the exact web `sessionStorage` keys below through the allowlisted WebKit bridge; file bytes remain in memory. The native leave guard covers unstaged statements, a selected advanced file, unsaved parser changes and active operations, while verified upload receipts bypass it to open their batch review. Price/account/transaction refreshes follow successful writes and rollback. Unknown upload outcomes remain visible and require inspecting history or explicitly refreshing before retrying; the UI never replays an import automatically.
>
> `native` marks implemented controls. Swift source parsing and portable model tests do not replace the pending macOS build and Demo interaction/visual pass, including file panels/drop, disclosures, alerts, parser mapping, restored sessions, rollback and staging stop/cancel behavior.

## Cross-cutting notes

- **Endpoints.** Net worth: `GET /api/info/net-worth?currency` for the chart and hero, the same with `limit`/`offset` for the table (`apps/frontend/src/lib/api/info.ts:472`); price refresh `POST /api/investments/refresh-prices` (`apps/frontend/src/lib/api/portfolio.ts:106`). By-account rows combine the accounts list, the portfolio summary and currency conversion on the client (`apps/frontend/src/pages/portfolio/net-worth/NetWorthPage.tsx:167`). Import: `POST /api/portfolio/import/csv/stream` (SSE progress), `GET/POST/PATCH/DELETE /api/portfolio/import/parsers`, `GET /api/portfolio/import/batches`, `GET /api/portfolio/import/batches/{id}/preview`, `POST /api/portfolio/import/batches/{id}/rows/investment-override`, `POST /api/portfolio/import/batches/{id}/commit`, `DELETE /api/portfolio/import/batches/{id}`, `POST /api/portfolio/import/reconciliation/preview` and `/commit` (`apps/frontend/src/lib/api/portfolioImports.ts:250` onward). Tax: settings `portfolio_tax_adjustments_v1`, `portfolio_tax_classifications_v1` and `widget_visibility` through the settings API; the Belgian profile, snapshots, freeze and filing state come from `BelgianTaxProfileContext`.
- **Shared components described once.** `VirtualDataTable` (search, sort, column filters, resize, infinite scroll) is used by the net-worth table; its rows here have no open, edit or context-menu actions. `PortfolioBrokerField` is used three times (statement rows in compact mode, advanced import, review footer). `useConfirmDialog` backs both import confirmations. `TaxYearSwitcher`, `YearActionsMenu`, `HistoricalYearBannerSection`, `MarkAsFiledDialog`, `SnapshotHistoryDialog` and `TaxProfileDialog` are shared with `/tax`.
- **Unsaved-work guard.** Both the advanced importer (file selected or parser config dirty) and the session (any statement not staged or completed) register with `UnsavedChangesContext`, which blocks in-app navigation with an alert and guards `beforeunload`. A review navigation after a single-file import bypasses it (`apps/frontend/src/pages/portfolio/PortfolioImportPage.tsx:336`).
- **Session persistence.** Staged statements and review settings survive reload in tab-scoped `sessionStorage`; file bytes do not, so unstaged statements are lost on reload. Native shares the same two metadata keys through the retained web page, with typed validation and serialized checkpoint writes.
- **Detection.** Web detection runs on the complete file; native uses the read-only `/api/portfolio/import/probe` endpoint with the same shared TypeScript predicates, including XLSX/XLS parsing and all account identities. Header preview remains bounded and independent of maintained detection.
- **Electron.** No `window.electronAPI` or `ElectronBridge` calls in scope. The only Electron-specific behaviour is the Go menu accelerator to Net worth. Printing uses the browser print path.
- **Toasts.** Import, rollback, parser, price refresh and adjustment outcomes are reported through Sonner toasts; a native screen needs an equivalent transient notification.
