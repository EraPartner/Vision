# Native parity inventory: Net worth, brokerage import and portfolio tax

> [!abstract] Scope
> Routes: `/portfolio/net-worth`, `/portfolio/import`, `/portfolio/import/:batchId/review`, `/portfolio/tax`. Source: `apps/frontend/src/pages/portfolio/net-worth/`, `apps/frontend/src/pages/portfolio/PortfolioImportPage.tsx`, `apps/frontend/src/pages/portfolio/PortfolioImportReviewPage.tsx`, `apps/frontend/src/pages/portfolio/tax/`, plus the parts of `apps/frontend/src/features/portfolio/`, `apps/frontend/src/features/imports/` and `apps/frontend/src/features/tax/` they render. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/203-vision-native-swift-app-target|ADR-203]].

Intent docs: [[docs/features/net-worth|Net Worth]], [[docs/features/portfolio-import|Portfolio Import]], [[docs/features/portfolio-tax|Portfolio Tax]], [[docs/reference/fund-holdings-import-contract|Fund Holdings Import Contract]]. Route table: [[docs/reference/frontend-routes|Frontend Routes]].

## Cross-cutting notes

- **Endpoints.** Net worth: `GET /api/info/net-worth?currency` for the chart and hero, the same with `limit`/`offset` for the table (`apps/frontend/src/lib/api/info.ts:472`); price refresh `POST /api/investments/refresh-prices` (`apps/frontend/src/lib/api/portfolio.ts:106`). By-account rows combine the accounts list, the portfolio summary and currency conversion on the client (`apps/frontend/src/pages/portfolio/net-worth/NetWorthPage.tsx:167`). Import: `POST /api/portfolio/import/csv/stream` (SSE progress), `GET/POST/PATCH/DELETE /api/portfolio/import/parsers`, `GET /api/portfolio/import/batches`, `GET /api/portfolio/import/batches/{id}/preview`, `POST /api/portfolio/import/batches/{id}/rows/investment-override`, `POST /api/portfolio/import/batches/{id}/commit`, `DELETE /api/portfolio/import/batches/{id}`, `POST /api/portfolio/import/reconciliation/preview` and `/commit` (`apps/frontend/src/lib/api/portfolioImports.ts:250` onward). Tax: settings `portfolio_tax_adjustments_v1`, `portfolio_tax_classifications_v1` and `widget_visibility` through the settings API; the Belgian profile, snapshots, freeze and filing state come from `BelgianTaxProfileContext`.
- **Shared components described once.** `VirtualDataTable` (search, sort, column filters, resize, infinite scroll) is used by the net-worth table; its rows here have no open, edit or context-menu actions. `PortfolioBrokerField` is used three times (statement rows in compact mode, advanced import, review footer). `useConfirmDialog` backs both import confirmations. `TaxYearSwitcher`, `YearActionsMenu`, `HistoricalYearBannerSection`, `MarkAsFiledDialog`, `SnapshotHistoryDialog` and `TaxProfileDialog` are shared with `/tax`.
- **Unsaved-work guard.** Both the advanced importer (file selected or parser config dirty) and the session (any statement not staged or completed) register with `UnsavedChangesContext`, which blocks in-app navigation with an alert and guards `beforeunload`. A review navigation after a single-file import bypasses it (`apps/frontend/src/pages/portfolio/PortfolioImportPage.tsx:336`).
- **Session persistence.** Staged statements and review settings survive reload in tab-scoped `sessionStorage`; file bytes do not, so unstaged statements are lost on reload. A native port needs an equivalent per-window store with the same Zod-validated shape.
- **Detection.** Format and broker-account detection for both the session and the advanced importer runs in the client on the full file (`apps/frontend/src/pages/portfolio/portfolioImportDetection.ts`), including XLSX/XLS parsing.
- **Electron.** No `window.electronAPI` or `ElectronBridge` calls in scope. The only Electron-specific behaviour is the Go menu accelerator to Net worth. Printing uses the browser print path.
- **Toasts.** Import, rollback, parser, price refresh and adjustment outcomes are reported through Sonner toasts; a native screen needs an equivalent transient notification.
