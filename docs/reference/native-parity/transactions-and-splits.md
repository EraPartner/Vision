## Cross-cutting notes

- **Electron-only:** the only desktop-specific path in scope is the native menu ⌘N (`new-transaction` bridge event) which routes through the same `?new=1` deep link. No `window.electronAPI` calls exist in these pages or features. Exports use a synthetic download (`downloadBlob`) in both web and desktop.
- **Shared `VirtualDataTable`:** one implementation provides search, column sort, column filter popovers, resizing, virtualisation, infinite scroll, scroll restoration per history entry, inline editing, row selection and context menus. On `/transactions` it runs in server mode (sort and search sent to the API, column filters still client-side on loaded rows); on `/owes` detail it runs fully local. Column widths and client column filters are not persisted.
- **Touch:** on coarse pointers a tap selects the row (same as click here because `onRowSelect` is set) — `apps/frontend/src/components/shared/VirtualDataTable.tsx:636`.
- **Focus return:** closing the inspector or Quick Look returns focus to the row that opened it without reselecting it — `apps/frontend/src/pages/TransactionsPage.tsx:138`, `apps/frontend/src/pages/TransactionsPage.tsx:157`.
- **Optimistic updates:** category and payee picks patch the row before the PATCH returns; single delete removes the row optimistically and rolls back on error — `apps/frontend/src/pages/TransactionsPage.tsx:595`, `apps/frontend/src/hooks/useTransactions.ts:231`.
- **Exclusion (is_active):** "Exclude from totals" / "Include in totals" appears in the row context menu, inspector footer, Status column toggle and the bulk menu; "Show excluded" in the View menu controls whether excluded rows are listed. Excluded rows render struck through. The shared `ExclusionToggle` and `ListFilterToggle` components are not rendered on either route (they are used by Home and Statistics).
- **Transfers:** creation via the Add sheet's Transfer kind (two legs + link), and linking two existing rows via bulk "Mark as internal transfer". There is no UI on these screens to unlink a transfer (`DELETE /api/transactions/transfers/:id`), no transfer badge on rows, and no surface for `GET /api/transactions/transfer-suggestions`.
- **Endpoints used:** `GET/POST /api/transactions`, `PATCH/DELETE /api/transactions/:id`, `GET /api/transactions/export/{csv,json}`, `POST /api/transactions/bulk-{delete,update,export,tag}`, `POST /api/transactions/transfers`, `GET/POST /api/recipients`, `GET /api/recipients/:id`, recipient update (default category), `GET/POST /api/tags`, `GET/POST /api/attachments/transaction/:id`, `GET /api/attachments/:id/download`, `DELETE /api/attachments/:id`, `GET /api/splits/transaction/:id`, `POST /api/splits/batch`, `POST /api/splits/bulk`, `GET /api/splits/owed`, `GET /api/splits/owed/:recipientId`, `GET /api/splits/owed/:recipientId/export/csv`, `POST /api/splits/:id/pay`, `POST /api/splits/:id/settle`, `POST /api/splits/owed/:recipientId/settle-all`, `DELETE /api/splits/:id` — `apps/frontend/src/lib/api/transactions.ts`, `apps/frontend/src/lib/api/splits.ts:93`, `apps/frontend/src/lib/api/attachments.ts:21`, `apps/frontend/src/lib/api/tags.ts:38`.
