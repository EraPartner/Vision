# Native parity inventory: Budgeting CSV import and import review

> [!abstract] Scope
> Routes: `/import`, `/import/:batchId/review`. Source: `apps/frontend/src/pages/ImportPage.tsx`, `apps/frontend/src/pages/ImportReviewPage.tsx`, `apps/frontend/src/features/imports/`, `apps/frontend/src/lib/importHandoff.ts`, and the CSV handlers in `apps/frontend/src/components/layout/ElectronBridge.tsx`. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/204-vision-native-swift-app-target|ADR-204]].
>
> Out of scope: the brokerage import (`/portfolio/import`, `PortfolioCsvColumnMapper`), which another inventory covers. The navigation entry points into `/import` from other screens (Transactions, Insights, Dashboard, Not found, onboarding) belong to those screens' inventories.

## Screens

### `/import` — Import & export

Component: `apps/frontend/src/pages/ImportPage.tsx`. Feature doc: [[docs/features/import|CSV Import]].

Layout: a two-column workspace (`max-w-7xl`). The main column holds the bank import card and Import history. The sidebar holds the export card and the collapsible "Setup and reference" card (`apps/frontend/src/pages/ImportPage.tsx:188`).

**Regions shown:**

- Page header: `importPage.title` "Import & export", subtitle `importPage.subtitle` "Import bank statements, or export your data as CSV or JSON.", and the page icon (`apps/frontend/src/pages/ImportPage.tsx:110`).
- Commit receipt card (`role="status"`), shown only after a review commit hands a receipt over in history state. It shows the title `importPage.commitReceiptTitle` "Import complete", the imported count as a rolling number with `importPage.commitReceiptImported` (plural: "transaction imported" / "transactions imported"), and a line with `importPage.commitReceiptDuplicates` ("{count} duplicates") · `importPage.commitReceiptErrors` ("{count} errors") (`apps/frontend/src/pages/ImportPage.tsx:115`).
- Bank import card: title `importPage.csvImport` "Import from your bank" and description `importPage.csvImportDesc` (`apps/frontend/src/features/imports/TransactionImportCard.tsx:388`).
- Selected-file summary inside the dropzone: the file name and its size in KB (`common.kb`) (`apps/frontend/src/features/imports/CsvDropzone.tsx:126`).
- Detected-columns panel (`FileHeadersPanel`), shown once a file is chosen. It shows a "Parsing headers…" state (`importPage.csvParsing`), or the unreadable notice `csvHeaders.unreadable` "Couldn't read columns. Is this a CSV file?", or the title `csvHeaders.title` "Detected columns", the count `csvHeaders.columns` "{n} columns", `csvHeaders.delimiterDetected` "Detected delimiter: {sep}" (only when the separator is auto-detected), one chip per header (mapped columns are highlighted), and up to 5 sample rows in a table (`apps/frontend/src/features/imports/FileHeadersPanel.tsx:105`). The client parses the file locally. It never sends the file to the backend for this preview (`apps/frontend/src/hooks/useCsvPreview.ts:100`).
- Saved-parser summary (read-only `dl`, labelled `importPage.savedParserSummary` "Saved setup"). It lists the date, payee, amount and memo columns, the separator, the date format and the number format (`apps/frontend/src/features/imports/TransactionImportCard.tsx:509`, rows built at `:372`).
- Progress panel (`role="status"`, live) while importing. It shows a phase label (`importPage.analyzing` "Analyzing file…" for `counting`, `importPage.parsingCSV` "Parsing CSV…" for `parsing`, `importPage.importingTxns` "Importing transactions…" for `importing`, `importPage.connecting` "Connecting…" for `connecting`), the percentage and a progress bar. During `importing` with a known total, it also shows `importPage.rows` "{current} / {total} rows", `importPage.imported` "{n} imported", `importPage.duplicates` "{n} duplicates" and, when non-zero, `importPage.errors` "{n} errors" (`apps/frontend/src/features/imports/TransactionImportCard.tsx:701`).
- Completion panel: `importPage.complete` "Import complete" plus `importPage.progressSummary` "{imported} imported · {duplicates} duplicates · {errors} errors" (`apps/frontend/src/features/imports/TransactionImportCard.tsx:755`).
- Failure panel (`role="alert"`): `importPage.failed` "Import failed. Try again." (`apps/frontend/src/features/imports/TransactionImportCard.tsx:779`).
- Footer hint (live region): the first missing piece, in order: `importPage.hint.file` "Choose a file to continue.", `importPage.hint.bank` "Choose your bank.", `importPage.hint.mapping` "Map the date, payee and amount columns.". Once nothing is missing it shows `importPage.hint.ready` "Ready to import." (`apps/frontend/src/features/imports/TransactionImportCard.tsx:230`, `:796`).
- Import history card: title `importHistory.title` "Import history" and description `importHistory.desc`. While loading it shows a section loader, and with no batches the empty state `importHistory.empty` "No imports yet" (`apps/frontend/src/features/imports/ImportHistoryCard.tsx:262`, `:284`, `:287`).
- Import history rows (10 per page). Each row shows the source file name, or `importHistory.batchFallback` "Batch #{id}" when there is none. It also shows a status badge from `importHistory.status.*` (Pending, Preparing, Validating, Matching, Awaiting review, Importing, Complete, Failed, Aborted), the adapter name, the start time (`yyyy-MM-dd HH:mm`) and, when present, `importPage.imported`, `importPage.duplicates` (when >0), `importPage.errors` (when >0) and `importHistory.remaining` "{n} remaining". A batch error summary appears in red (`apps/frontend/src/features/imports/ImportHistoryCard.tsx:61`, `:142`).
- Pagination caption `importHistory.page` "Page {page} of {total}", shown only when there is more than one page (`apps/frontend/src/features/imports/ImportHistoryCard.tsx:305`).
- Export card: title `importPage.csvExport` "Export your data", description `importPage.csvExportDesc`, sub-heading `importPage.exportFilters` "Export filters", and the filter note `importPage.exportNote` "Leave fields empty to include all records." (`apps/frontend/src/features/imports/ExportCard.tsx:89`, `:99`, `:202`).
- Setup and reference card: title `importPage.setupReference` "Setup and reference" and description `importPage.setupReferenceDesc`. It is collapsed by default (`apps/frontend/src/pages/ImportPage.tsx:97`, `:201`).
- Payees from CSV card (inside Setup and reference): title `importPage.recipientsImport` "Payees from CSV", description `importPage.recipientsImportDesc`, and the result line `importPage.resultSummary` "{imported} imported, {skipped} skipped, {errors} errors" (`apps/frontend/src/features/imports/RecipientsImportCard.tsx:9`, `apps/frontend/src/features/imports/SimpleImportCard.tsx:99`).
- Categories from CSV card (inside Setup and reference): title `importPage.categoriesImport` "Categories from CSV", description `importPage.categoriesImportDesc`, and the same result line (`apps/frontend/src/features/imports/CategoriesImportCard.tsx:9`).
- Supported banks card (inside Setup and reference): title `importPage.supportedBanks` "Supported banks", then a loading badge (`importPage.supportedLoading`), one badge per adapter name, or `importPage.noSupportedParsers`. The footnote reads `importPage.noSupportedBank` "Can't see your bank? Try Custom." (`apps/frontend/src/features/imports/SupportedBanksCard.tsx:20`).

**URL state:** no query parameters. The page reads a transient `importCommitReceipt` object from router history state (`location.state`). It validates the object (non-negative finite counts, and `YYYY-MM-DD` dates only) and then replaces the history entry with `state: null`, so a reload does not replay the receipt (`apps/frontend/src/pages/ImportPage.tsx:41`, `:98`, `:103`).

## Cross-cutting notes

- **Electron CSV handoff (frontend side).** `ElectronBridge` listens through the bridge method `onCsvOpen` (the IPC channel `app:csv-opened`, used for Finder "Open With" and dock drops). It rebuilds a `File` from `{ name, content }`, registers it with `registerPendingImportFile`, and navigates to `/import` (`apps/frontend/src/components/layout/ElectronBridge.tsx:119`). A window-level `dragover`/`drop` listener swallows every file drop. Unless the drop lands inside a `[data-dropzone]`, a `.csv` file is registered the same way and the app navigates to `/import`. Other files are ignored (`apps/frontend/src/components/layout/ElectronBridge.tsx:129`). The handoff slot holds one file for 30 seconds (`apps/frontend/src/lib/importHandoff.ts:15`). `TransactionImportCard` consumes it on mount and pre-fills the dropzone (row 25 on `/import`). A native port needs the same flow: an `.onOpenURL`/document-open or drop target that lands on the import screen with the file pre-selected and waits for the user to choose a bank.
- **Two import result paths.** Built-in banks use the SSE stream (live progress, cancellable). Custom and saved parsers use a single multipart request (no live progress events). Either path can come back as "review required", which routes to `/import/:batchId/review` (`apps/frontend/src/features/imports/TransactionImportCard.tsx:267`, `apps/frontend/src/lib/api/imports.ts:119`).
- **Review is per group.** Every payee and category change is applied by one request per staged row in the group (`Promise.all`), not by one bulk call (`apps/frontend/src/features/imports/useImportReviewData.tsx:157`).
- **Shared components described once:** `CsvDropzone` (rows 3-8, reused in rows 42 and 45), the `CsvFormatSelects` selects (rows 13-16, 40, 41, 44), `useConfirmDialog` (three confirms), `DatePicker` and `MultiCombobox` popovers, and the `RecipientCombobox` and `CategoryCombobox` popovers.
- **Backend endpoints used:** `GET /api/info/supported-adapters`; `GET|POST /api/import/parsers`; `PATCH|DELETE /api/import/parsers/:id`; `POST /api/import/csv/stream`; `POST /api/import/csv/custom`; `POST /api/import/recipients`; `POST /api/import/categories`; `GET /api/import/batches?limit&offset`; `DELETE /api/import/batches/:id`; `GET /api/import/batches/:id/preview`; `POST /api/import/batches/:id/rows/:rowId/override`; `POST /api/import/batches/:id/rows/:rowId/category-override`; `POST /api/import/batches/:id/commit`; `PATCH /api/recipients/:id`; `GET /api/accounts?active=all`; `GET /api/recipients`; `GET /api/info/banks`; `GET /api/transactions/export/csv|json` (`apps/frontend/src/lib/api/imports.ts`, `apps/frontend/src/lib/api/info.ts:31`).
- **Downloads.** Export goes through `downloadBlob` (blob → anchor click). A native port needs a save panel or a direct write to Downloads (`apps/frontend/src/features/imports/ExportCard.tsx:72`).

## Gaps and unsure

- **Page title conflict (unverified intent).** [[docs/features/import]] and [[docs/adr/183-remaining-screens-redesign|ADR-183]] say the page is titled "Import", but `importPage.title` in `en.json` is "Import & export". The code renders "Import & export".
- **Progress phase labels do not match the backend (unverified at runtime).** The progress panel labels only the phases `counting`, `parsing`, `importing` and `connecting`, and shows the row, imported and duplicate counts only for `importing` (`apps/frontend/src/features/imports/TransactionImportCard.tsx:709`, `:723`). The backend emits `staging`, `validating`, `matching` and `committing` (`apps/node-backend/src/lib/importProgress.ts:21`). During a real import the phase label may therefore be blank and the row counts may never show. Only the percentage and the bar would move.
- **Cancel is a no-op for custom imports (unverified at runtime).** The Cancel button appears whenever `loading` is true, but `abortRef` is set only on the SSE path. During a custom or saved-parser import, clicking Cancel does nothing (`apps/frontend/src/features/imports/TransactionImportCard.tsx:362`).
- **Handoff is pre-fill, not auto-start.** [[docs/features/import]] says the card "begins the import flow automatically". The code only sets the file, and the user must still choose a bank and click Import (`apps/frontend/src/features/imports/TransactionImportCard.tsx:218`).
- **Bank Select option labels come from the backend.** Adapter display names (`adapter.name`) come from `GET /api/info/supported-adapters`, not from i18n. The adapter set (Belfius, Revolut, ING, KBC, BNP Paribas Fortis, SABB, Wise, Vision, per the feature doc) was not confirmed from code in this inventory.
- **Parked batches in history have no discard.** An `awaiting_review` batch shows only Resume review. Discarding is possible only from the review page, and Roll back requires status `complete` (`apps/frontend/src/features/imports/ImportHistoryCard.tsx:81`, `:198`).
- **Invalid `batchId`.** For a non-numeric `batchId` the query is disabled. The page then appears to render the error state with an empty message and no Retry button (unverified).
- **Accordion keyboard behaviour** is assumed from Radix defaults. No custom key handlers exist (unverified).
- **Doc mentions an ad-hoc "custom" import that is not saved.** That is the "Custom or other" source with no Save. It shares the editor with saved parsers. No separate UI exists.
- **Vision Native, phase 3d.** `/import` and `/import/:batchId/review` draw natively in every mode (`apps/native/Sources/VisionNativeUI/ImportExportView.swift`, `ImportComponents.swift`, `ImportSidebarViews.swift`, `ImportReviewView.swift`; models in `apps/native/Sources/VisionNativeCore/Screens/Imports/`). Below 960 pt the sidebar column (export card, Setup and reference) stacks under the main column. Export CSV and Export JSON open a save panel; the success toast appears only after the file is saved, and a cancelled panel posts no toast. Both pages share one toast stack (at most three toasts, newest at the bottom), so the commit and discard toasts stay visible after the review returns to `/import`; the Review accounts action toast does not bind ⌘Z. After a native commit the planned-payment and account lists refresh on their next load instead of being invalidated at once. A CSV dropped on a web-drawn route still goes to the hidden web card; a drop on any native screen, and every Finder or dock open (also at cold launch, before `app_settings` is read, when the web card gets it too), pre-fills the native card. A file handed off while an import runs waits until that import ends. An import that parks its batch after the user left `/import` does not navigate: the card resets and an `importHistory.status.awaiting_review` toast with a `importHistory.resumeReview` action opens the review. A dropped or picked file that cannot be read (a folder, unreadable, or above 25 MiB) toasts `importPage.toast.noFile`. Cancel posts only `importPage.toast.importCancelled`; the web card also shows a `importPage.toast.serverError` toast for the aborted stream.
- **Entry points from other screens** (Transactions empty state, Insights, Dashboard needs-attention, Not found, onboarding wizard → review, Electron menu `navigate` payloads, command palette entry `nav.importExport`) are not inventoried here (unverified ownership: shell and those screens' inventories).
