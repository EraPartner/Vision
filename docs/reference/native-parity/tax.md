# Native parity inventory: Belgian tax

> [!abstract] Scope
> Routes: `/tax`. Source: `apps/frontend/src/pages/TaxOverviewPage.tsx`, `apps/frontend/src/features/tax/`, plus the shared `features/reports/ExportDialog.tsx` and `components/shared/WidgetVisibilityDialog.tsx` as opened from `/tax`. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/204-vision-native-swift-app-target|ADR-204]].

> [!info] Native implementation (phase 3h; Mac parity review pending)
> `/tax` renders in `TaxOverviewView` with native year actions, widgets, charts, deductions and the six-step profile sheet. `TaxOverviewModel` and `TaxDashboardModel` use backend overview/dashboard data; `TaxProfileModel` previews through `computeBelgianTax` and persists write-through edits through existing atomic settings CAS. `TaxActionsModel` owns snapshot/freeze/file/history changes, and `TaxYearCSV` uses a native save panel. Fiscal formulas stay shared TypeScript; money decodes directly as Decimal. Phase 3p PDF export opens `NativeReportSheet` with `export=pdf`, preserving `year`; File → Print captures the currently loaded visible Tax page. Native status records implemented actions, not a verified phase exit: macOS build and synthetic visual/keyboard verification remain pending. See [[docs/api/belgian-tax|the API contract]] and [[docs/architecture/native-app|native architecture]].

Files outside `/tax` but inside `features/tax/` (`PortfolioProfileInputsCard`, `BelgianPortfolioRulesCard`, `PortfolioBudgetCard`, `PortfolioTaxSummaryCards`, `RecordedVsManualCard`, `YearlyCostTrendCard`, `TaxTypesBreakdownCard`, `HistoricalYearBanner`, `HistoricalYearBannerSection`) are rendered only by `/portfolio/tax` (`apps/frontend/src/pages/portfolio/tax/PortfolioTaxPage.tsx`) and belong to the portfolio inventory. `TaxYearSwitcher`, `YearActionsMenu`, `TaxProfileDialog` and `TaxDisclaimerBanner` are shared with that page.

## Cross-cutting notes

- **Engine location.** All figures (PIT, household split, quotient, own-home credits, chart PIT per bar, monthly reserve, CSV) are computed in the browser from `apps/frontend/src/lib/belgianTax/` via `useTaxOverviewData` (`apps/frontend/src/hooks/useTaxOverviewData.ts:66-440`) and the store resolvers `resolveBelgianTaxCalculation` / `resolveBelgianTaxHouseholdResult` (frozen calculation first, then that year's household). The native computation endpoint now exists; the web store retains its existing calculation path through the shared TypeScript modules.
- **Persistence.** The profile is stored as settings through `PUT /api/settings/{key}` with an optimistic-concurrency `expected` baseline (`apps/frontend/src/lib/api/settings.ts:47-75`), debounced 500 ms, keys `belgian_tax_household_v2`, `belgian_tax_household_snapshots_v2`, `belgian_tax_profile_snapshot_meta_v1`; the v1 keys `belgian_tax_profile` and `belgian_tax_profile_snapshots_v1` are read for the one-time upgrade (`apps/frontend/src/contexts/BelgianTaxProfileContext.tsx:37-41`, `:182-197`, `:227-247`). A failed save raises the toast `settings.saveFailed` (`apps/frontend/src/contexts/BelgianTaxProfileContext.tsx:254-266`). Freeze/file/unfile, snapshot creation, profile edits, deduction-candidate confirmations all go through this path.
- **Data endpoints read on this screen.** `GET /api/aggregations/monthly-summary` and `GET /api/aggregations/category-pivot` via `useStatistics` (income by month and by category with `incomeByOwnerMonths`; `apps/frontend/src/hooks/useStatistics.ts:344-367`), investments with transactions via `usePortfolio` (portfolio taxes for the year and the years list), `GET /api/info/deduction-candidates?year=`, `GET /api/categories/tree`, exchange rates via `useCurrencyConverter`. Export: `POST /api/reports/tax`.
- **Viewed year.** `viewedYear` is transient store state shared with `/portfolio/tax`; it drives the masthead, flow, breakdowns, charts, comparison and both year menus. It is mirrored to `?year=`. Exceptions that use the live year (see Gaps): Suggested deductions card, Deduction candidates card, the empty-state and "Add / edit" profile sheet triggers.
- **Partner attribution (ADR-201).** Recorded income and deduction candidates are split by account owner: `me` → partner A, `partner` → partner B, `joint` 50/50; one-partner households attribute everything to A (`apps/frontend/src/lib/belgianTax/partnerAttribution.ts`).
- **Shared components.** `TaxYearSwitcher`, `YearActionsMenu` (with different page items), `TaxProfileDialog` and `TaxDisclaimerBanner` are also used by `/portfolio/tax`; describe them once natively.
- **Electron.** No Electron bridge calls on this screen. CSV export uses an anchor download of a Blob (`apps/frontend/src/lib/downloadBlob.ts:8-19`); the PDF export goes through `postReportDownload`.
- **Print.** Printing `/tax` prints the on-screen report with a print stylesheet keyed on `data-print-page="tax"`; there is no print button.
- **Formatting.** Currency through the shared formatter (app currency and decimals; whole euros in the trend strip and comparison), percentages through `usePercentFormatter`, month ticks through `Intl.DateTimeFormat` in the app number-format locale.

## Gaps and unsure

native; current-page print freezes the loaded year, visible widgets, comparison year, disclosure state
and deductions without queries or fiscal recalculation. Its new print Core proof is separate from the
1,271-test combined phase-3p proof. Native markers record implementation, not rendered verification.

- Resolved computation prerequisite (ADR-204 §6): the backend operation uses the shared TypeScript engine. SwiftUI must display these results, preserve frozen filings, and keep the implemented profile workflows; it must not reproduce tax formulas.
- Doc/code conflict: `docs/features/belgian-tax.md` (overview-page composition) says `TaxYearSwitcher` and `YearActionsMenu` live inside `TaxFilingMasthead`; in code they are in the page header actions, and the masthead header comment says so (`apps/frontend/src/features/tax/TaxFilingMasthead.tsx:11-12`, `apps/frontend/src/pages/TaxOverviewPage.tsx:157-176`).
- Doc/code conflict: the doc says an incoming `?year=` is accepted within ±30 years of the live year; code accepts [live − 30, live + 1] or any snapshot year (`apps/frontend/src/hooks/useTaxYearParam.ts:64-67`).
- `SuggestedDeductionsCard` reads the live profile and calculation, and `DeductionCandidatesCard` fetches candidates for the live `profile.taxYear`, not the viewed year; both "Add / edit" and the empty-state "Set up tax profile" open the sheet without `targetYear` (live year). Unverified whether intended.
- The income vs reserve card title `tax.incomeBreakdown.title` says "(last 12 months)" also when a historical year is viewed and the series covers that calendar year.
- `ProfileNumberInput` passes `min`/`max`/`step` to a `type="text"` input, where browsers ignore them; ranges such as surcharge 0-9, loan share 0-100 and mortgage start year 1990-current year are not enforced. Only the explicit code bounds (birth year and chèque-habitat year 1900-2200, woonbonus children 0-1000, service vouchers ≥ 0) and the Zod rules apply.
- `PartnerReductionInputs.medicalExpenses` exists in the model (`apps/frontend/src/features/tax/profile-steps/householdEditing.ts:297`) but has no input in any step; unverified whether the engine uses it.
- The pension scheme select has no visible label or `aria-label` (`apps/frontend/src/features/tax/profile-steps/ExemptionsStep.tsx:227-248`).
- Residences have no per-row remove; "Reset" removes all of them.
- The tax profile sheet has no cancel or discard; closing keeps every edit, and Save only sets `profileConfigured`. A native sheet must keep write-through semantics or document the change.
- The comparison year select and the deduction-candidate "Applied" badge are component state and reset on reload.
- Keyboard behaviour of `SegmentedControl` and `DatePicker` was not inspected in detail (unverified).
