## Cross-cutting notes

### Persistence and backend endpoints used by the shell

- App settings (`updateAppSettings`), dashboard settings (`updateSettings`) and theme settings are Zustand stores hydrated from and debounce-persisted (500 ms) to the settings API (`/api/settings`, conditional whole-value replacement, ADR-173); a rejected save shows `settings.saveFailed` without rolling back ([[docs/features/settings|Settings]]). Direct setting writes from the shell: `includeTransfers`, `cost_basis_method`, `dismissed_recurring_patterns`, `brokerage_cash_category_ids`, `onboarding_complete`, and, outside Electron, `backup_settings` / `services_settings` — `apps/frontend/src/lib/api/electron.ts:163`, `apps/frontend/src/lib/api/electron.ts:210`.
- Other endpoints: `GET /api/info/exchange-rates?db_only=true`, `POST /api/info/exchange-rates/refresh`, planned transactions (upcoming banner and badge), needs-category count, insights count, monitor notifications (sidebar badges), `GET /api/admin/update/check` (web update status), `GET /api/market/quote`, `GET /api/recipients`, `GET /api/ai/status`, `GET /api/ai/models`, `GET /api/ai-research/status`, `GET|PUT /api/ai-research/agentcloak-desktop`, `GET|PUT|DELETE /api/research/provider-keys[/{provider}]`, `GET /api/info/supported-adapters`, `POST /api/categories`, `POST /api/import/csv`.
- Per-browser localStorage state the native app must re-home: `vision.sidebar.collapsed`, `vision.sidebar.hiddenSections`, `vision.palette.recents`, `vision.lastRoute`, `vision.startupSection`, `vision.onboarding.draft.v1`, `dismissed_upcoming_planned_payments`, `fx-status-banner-dismissed-at`, `vision.backup.passphrase.reminder.dismissed`. Manual backups bundle every `LOCAL_STORAGE_KEYS` value and restores write them back — `apps/frontend/src/features/settings/sections/BackupSection.tsx:130`, `apps/frontend/src/hooks/useRestoreBackup.tsx:71`.

## Phase 3p native ownership

The mounted native palette and shortcuts help, FX/upcoming-payment banners and seven-step onboarding
replace their source overlays under strict capability flags. Fixed TypeScript palette callbacks retain
source calculation/parsing behavior. App-lifetime dismissal/draft queues drain before restore; setup
completion joins the common settings writer. The shared PDF sheet also replaces `ExportDialog`
under its capability; its controls are inventoried in
[[docs/reference/native-parity/home-and-statistics|Home and Statistics]],
[[docs/reference/native-parity/portfolio-holdings|Portfolio holdings]] and
[[docs/reference/native-parity/tax|Tax]].

`NativeShellOverlayHost.swift` presents one sheet and keeps covered native overlays mounted.
Only the active overlay receives pointer/keyboard interaction, accessibility exposure and notice
announcements. Priority is palette, shortcuts, Settings, reports, then onboarding. Its AppKit
responder bridge records weak per-overlay controls, including the owning field control and text
selection instead of the shared field editor. When a covered overlay becomes active again, it
restores an attached, visible and enabled responder and valid selection.
`NativeOverlayFocusReturn.swift` separately captures the route-window opener and returns focus
after final sheet dismissal, with graph, underlying-route, window and reload/restore fences.
Detached/reparented controls, a newer overlay or another key window reject the return.

`NativeCommandPaletteView.swift` requests initial search focus and implements Arrow Up/Down,
Home/End, modifier navigation, Return activation and container-level Escape; Close also has the
cancel shortcut. `NativeShortcutsHelpView.swift` has a
cancel-action Close control. `NativeOnboardingView.swift` has default-action Next/Finish,
cancel-action Close and explicit Escape completion; a step change requests accessibility focus
on its heading. Close, Escape and Skip setup all complete onboarding through the writer; failed
completion retains the wizard. Interactive dismissal is blocked during onboarding, report
submission and graph reload/restore suspension.

These mappings describe implemented controls. The source action tables retain React behavior as
the comparison baseline; they do not certify macOS sheet outside-click behavior, full keyboard
routing, actual route-opener focus restoration, rendered English/Dutch layouts or VoiceOver operation.
The macOS package and synthetic Demo gates remain open. See [[docs/architecture/native-app#Shell overlays and reports (phase 3p)|native architecture]],
[[docs/features/onboarding|setup flow]] and [[docs/diagrams/index|structural diagrams]].
