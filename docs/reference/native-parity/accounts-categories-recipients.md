# Native parity inventory: Accounts, categories, payees and tags

> [!abstract] Scope
> Routes: `/accounts`, `/accounts/:id`, `/categories`, `/recipients`. Source: `apps/frontend/src/pages/AccountsPage.tsx`, `apps/frontend/src/pages/AccountDetailPage.tsx`, `apps/frontend/src/pages/CategoriesPage.tsx`, `apps/frontend/src/pages/RecipientsPage.tsx`, `apps/frontend/src/features/accounts/`, `apps/frontend/src/features/categories/`, `apps/frontend/src/features/recipients/`, and the shared tag controls in `apps/frontend/src/components/shared/`. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/203-vision-native-swift-app-target|ADR-203]].

> [!note] Terminology
> The code and routes say "recipient". The English UI says "payee". Both words name the same entity in this page.

### `/accounts` — Accounts

Component: `apps/frontend/src/pages/AccountsPage.tsx`. Feature doc: [[docs/features/accounts|Accounts]].

**Regions shown:**

- Page header with title `accounts.title` ("Accounts"), subtitle `accounts.subtitle` ("Your accounts across budgeting, portfolio and research."), and the page icon. Source: `apps/frontend/src/pages/AccountsPage.tsx:448`.
- Loading skeleton. Source: `apps/frontend/src/pages/AccountsPage.tsx:455`.
- Error state using `PageError` with the API error message. Source: `apps/frontend/src/pages/AccountsPage.tsx:464`.

Empty groups are omitted. Rows are sorted by display label with a locale-aware, numeric collator, with the account id as the tie-breaker. Sources: `apps/frontend/src/features/accounts/groupAccounts.ts:48`, `apps/frontend/src/features/accounts/groupAccounts.ts:67`, `apps/frontend/src/pages/AccountsPage.tsx:482`.

Source: `apps/frontend/src/pages/AccountsPage.tsx:385`.
- Each account row shows:
  - A leading icon for the account type. Source: `apps/frontend/src/pages/AccountsPage.tsx:63`.
  - The display name, falling back to the name.
  - An `accounts.archived` ("Archived") badge on inactive accounts and an `accounts.notInNetWorth` ("not in net worth") badge where it applies. Source: `apps/frontend/src/pages/AccountsPage.tsx:322`.
  - A meta line: the type (`accounts.type.*`), currency and institution, separated by " · ". Source: `apps/frontend/src/pages/AccountsPage.tsx:175`.
  - The drift chip. `accounts.driftBadge` reads "{amount} off your statement", followed by "· `accounts.driftBadgeStatement`" ("statement of {date}") when a statement date exists.   - A provenance subline: `accounts.provenance.anchored.*` ("Statement of {date} plus {count} entries since") or `accounts.provenance.sum.*` ("Sum of {count} entries"). Source: `apps/frontend/src/features/accounts/balanceProvenance.ts:51`.
  - For brokerage accounts, a cash line: `accounts.portfolio.cash` ("Cash") with the amount and its provenance. Source: `apps/frontend/src/pages/AccountsPage.tsx:215`.
  - When a balance is incomplete, the warning `accounts.balanceIncomplete` and each unconverted currency part followed by `accounts.balanceExcluded` ("left out of the converted total"). Source: `apps/frontend/src/pages/AccountsPage.tsx:235`.
- Trailing value on each row:
  - Cash-type accounts show the computed balance. Source: `apps/frontend/src/pages/AccountsPage.tsx:302`.
  - Portfolio-type accounts show the holdings value with `accounts.portfolio.holdings` ("Holdings value"), plus `accounts.portfolio.pnl` ("Broker P&L") as a signed amount in the gain or loss color. Without a position they show `accounts.portfolio.noAssignedHoldings` ("No assigned holdings"), or `accounts.trackedInPortfolio` ("Tracked in Portfolio") when no metrics are available. Source: `apps/frontend/src/pages/AccountsPage.tsx:263`.
  - Rows end in a disclosure chevron.
- Net cash card: `accounts.netCash` ("Net cash") with `accounts.netCashHint`, and the warning `accounts.totalIncomplete` when it applies. The total sums the active, in-net-worth, non-portfolio accounts in the display currency. Sources: `apps/frontend/src/pages/AccountsPage.tsx:501`, `apps/frontend/src/features/accounts/groupAccounts.ts:117`.
- Archived group: collapsed by default, with a header showing the count and a subtotal. Source: `apps/frontend/src/pages/AccountsPage.tsx:530`.

**URL state:** none. `AccountsPage` reads no query parameters, so the retired `/accounts?account=<id>` form opens the hub.

#### Sheet: Add account / Edit account (`AddAccountDialog`)

Opened from: rows 1 and 2 above in create mode, and from `/accounts/:id` row 3 in edit mode. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx`. This is a right-hand sheet. The title is `accounts.addTitle` ("Add account") or `accounts.editTitle` ("Edit account").

Fields:

- Name (`accounts.field.name`): text input with placeholder `accounts.field.namePlaceholder` and hint `accounts.field.nameHint`. It is required and limited to 200 characters. Zod requires a non-empty trimmed value and trims it on save. A missing name blocks submission silently and disables the submit button. In create mode the display name copies the name until the user edits the display name. Sources: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:429`, `apps/frontend/src/features/accounts/accountFormSchema.ts:17`.
- Display name (`accounts.field.displayName`): text input with placeholder `accounts.field.displayNamePlaceholder`, limited to 200 characters and trimmed. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:443`.
- Institution (`accounts.field.institution`): text input, limited to 200 characters and trimmed. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:460`.
- Currency (`accounts.field.currency`): select over `SUPPORTED_CURRENCIES`. An unknown existing code is prepended to the list. Zod applies `currencyCode("EUR")`. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:473`.
- Type (`accounts.field.type`): select with checking, savings, brokerage, crypto_exchange, wallet, pension and liability, each labelled `accounts.type.*`. Changing the type pre-fills liquidity, spendable, has_cash_sleeve and tax_wrapper for any flag the user has not edited. Choosing a holdings-only type clears the opening balance. Sources: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:293`, `apps/frontend/src/features/accounts/AddAccountDialog.tsx:497`.
- Opening balance (create mode only, hidden for wallet and crypto exchange): decimal text input. Its label is `accounts.openingBalance.createLabel` ("Opening balance"), or `accounts.openingBalance.createDebtLabel` ("Outstanding debt") for a liability. The placeholder is `accounts.openingBalance.createPlaceholder` ("Optional"). The field is optional and parsed with the app's number format. An invalid value shows `accounts.openingBalance.invalid` and receives focus. Hint: `accounts.openingBalance.createHint`. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:519`.
- As of date (`accounts.openingBalance.dateLabel`): a date picker that can be cleared and defaults to today. It is required when an opening balance is entered and shows `validation.required` otherwise. Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:565`.
- Advanced section, collapsed in create mode and expanded in edit mode:
  - Owner (`accounts.field.owner`): select with me, partner and joint (`accounts.owner.*`), hint `accounts.field.ownerHint`.
  - Liquidity (`accounts.field.liquidityClass`): select with liquid, semi_liquid and illiquid (`accounts.liquidity.*`), hint `accounts.field.liquidityHint`.
  - Spendable (`accounts.field.spendable`): switch, hint `accounts.field.spendableHint`.
  - Include in net worth (`accounts.field.inNetWorth`): switch.
  - Source: `apps/frontend/src/features/accounts/AddAccountDialog.tsx:625`.

#### Dialog: Reconcile balance (`ReconcileDialog`)

Opened from: `/accounts` rows 5 and 11, and `/accounts/:id` rows 12 and 15. Source: `apps/frontend/src/features/accounts/ReconcileDialog.tsx`. Title: `accounts.reconcile.title`. Description: `accounts.reconcile.description`.

Regions:

- Statement balance (`accounts.reconcile.statementLabel`) and computed balance (`accounts.reconcile.computedLabel`).
- `accounts.reconcile.reconcilableLabel` ("Reconciles against ({currency})") with the hint `accounts.reconcile.reconcilableHint`, shown only when the reconciliation base differs from the computed balance.

- A backdated-reading alert, `accounts.reconcile.backdatedWarning`.
- Three resolution blocks, each with a heading and a description: accept, adjustment, and backfill.
- Source: `apps/frontend/src/features/accounts/ReconcileDialog.tsx:379`.

Fields:

- Statement currency (`accounts.reconcile.currencyLabel`): select. It appears only for multi-currency cash accounts that hold more than one currency. Changing it clears the reading. Source: `apps/frontend/src/features/accounts/ReconcileDialog.tsx:388`.
- New statement reading (`accounts.reconcile.readingLabel`): decimal text input. Its placeholder is the stored statement figure. It is parsed strictly with the app number format, rounded to cents, and described by the hint `accounts.reconcile.readingHint`. Source: `apps/frontend/src/features/accounts/ReconcileDialog.tsx:479`.
- As of (`accounts.reconcile.readingDateLabel`): date picker that can be cleared and defaults to today. It must be a valid YYYY-MM-DD date. Source: `apps/frontend/src/features/accounts/ReconcileDialog.tsx:495`.

### `/accounts/:id` — Account detail (ledger)

Component: `apps/frontend/src/pages/AccountDetailPage.tsx`. Feature doc: [[docs/features/accounts|Accounts]].

**Regions shown:**

- Loading uses `SectionLoader`. Error uses `PageError`. Not found shows `accounts.detail.notFoundTitle` and `accounts.detail.notFoundDescription`. Source: `apps/frontend/src/pages/AccountDetailPage.tsx:324`.
- Page header: the display name as the title, a subtitle of type, currency and institution, an `accounts.archived` badge when the account is inactive, and a back link. Source: `apps/frontend/src/pages/AccountDetailPage.tsx:394`.
- Balance card, headed `accounts.detail.balance` ("Balance"):
  - The computed balance, with a tooltip.
  - The provenance subline.
  - `accounts.detail.noBalance` when no balance exists, or `accounts.trackedInPortfolio` for holdings-only accounts.
  - The drift chip.
  - A sparkline (aria `accounts.detail.sparklineAria`) of up to the 100 most recent running balances in the account currency. It is drawn green, red or neutral according to the trend.
  - Sources: `apps/frontend/src/pages/AccountDetailPage.tsx:520`, `apps/frontend/src/pages/AccountDetailPage.tsx:236`.
- Holdings card (portfolio types): `accounts.detail.holdings`, the oversold badge, `accounts.portfolio.holdings` value, and `accounts.portfolio.pnl` signed amount, or `accounts.portfolio.noAssignedHoldings`. It includes loading and error states. Source: `apps/frontend/src/pages/AccountDetailPage.tsx:610`.
- Upcoming planned transactions card (not shown for holdings-only accounts):
  - Title `accounts.detail.upcomingPlanned` and hint `accounts.detail.upcomingPlannedHint`.
  - A table with Date (`txPage.col.date`), Description (`txPage.field.description`: payee, memo, or `accounts.detail.unlabelled`) and Amount (`txPage.col.amount`, signed).
  - A truncation note, `accounts.detail.upcomingPlannedTruncated`.
  - Data source: `GET /api/planned-transactions` filtered by account_id, active, not executed, limit 5000.
  - Sources: `apps/frontend/src/pages/AccountDetailPage.tsx:682`, `apps/frontend/src/hooks/useAccountPlannedTransactions.ts:13`.
- Ledger card (not shown for holdings-only accounts):
  - Title `accounts.detail.ledgerTitle` ("Ledger") and count `accounts.detail.ledgerCount.*`.
  - The since banner, `accounts.detail.sinceBanner`.
  - A table with Date, Description (payee or memo, with the memo as a second line), Category (`txPage.col.category`), Amount (signed and colored by `amountClass`) and Balance (`txPage.field.balance`, the server `running_balance`, or "—").
  - Rows appear dimmed while placeholder data shows.
  - `accounts.detail.noLedger` when the account has no ledger, and an empty state `accounts.detail.noTransactions`.
  - Data source: `GET /api/transactions?account_id=&limit=&sort_by=date&sort_dir=desc&include_balance=true`.
  - Sources: `apps/frontend/src/pages/AccountDetailPage.tsx:785`, `apps/frontend/src/hooks/useTransactions.ts:63`.
- Details card, `accounts.detail.details`, a definition list:
  - type
  - currency
  - owner
  - liquidity
  - institution (if set)
  - spendable (`common.yes` or `common.no`)
  - in net worth
  - Source: `apps/frontend/src/pages/AccountDetailPage.tsx:358`.

**URL state:** the route parameter `:id`, which must be a positive integer. The page reads the query parameter `since` and accepts it only when it matches `YYYY-MM-DD`. It filters ledger rows on the client to those dated on or after that day, and stops Load more once an older row has loaded. Clearing the banner removes `since` with a replace write. Sources: `apps/frontend/src/pages/AccountDetailPage.tsx:155`, `apps/frontend/src/pages/AccountDetailPage.tsx:217`. The Reconcile dialog writes `since` (Reconcile row 8).

## Cross-cutting notes

- **Electron:** no `window.electronAPI` or bridge calls exist in this scope.
- **Row menus:** every ••• menu uses the shared `RowMenu` (`apps/frontend/src/components/shared/RowMenu.tsx:61`). Its trigger's accessible name is the localized `label`.
- **Confirmation alerts:** the account, category, payee and pattern deletes use `useConfirmDialog`. When no label is passed it falls back to `common.confirm` for the title and the confirm button, and to `common.cancel` for the cancel button (`apps/frontend/src/hooks/useConfirmDialog.tsx:83`).
- **Undo toasts:** category and payee status flips use `undoToast` with a time-to-live (`apps/frontend/src/lib/undoToast.ts:28`).
- **Amounts:** account amounts render with `Money` or `useCurrencyFormatter` in the account's native currency. Hub subtotals and Net cash convert into `appSettings.defaultCurrency` (EUR fallback) through `useCurrencyConverter`. A missing exchange rate marks the total incomplete; the amount is never treated as 1:1.
- **Hub dependency:** the Accounts hub and the detail page both depend on the portfolio summary (`getPortfolioSummary({currency})`) for broker holdings and P&L, through `getBrokerAccountMetrics`.
- **Backend endpoints used in this scope:**

## Gaps and unsure

- **Tag management (unverified):** there is no tag management UI. `apps/frontend/src/lib/api/tags.ts:26` (`updateTag`) and `:33` (`deleteTag`) have no UI callers, so the "Soft-delete tags" capability and tag color editing in [[docs/features/tags|Transaction Tags]] cannot be reached from the frontend. A native port has nothing to match. This is a doc/code gap.
- **Category reordering:** the tree has no drag-and-drop or manual reorder. Siblings are always sorted by name (`apps/frontend/src/pages/CategoriesPage.tsx:118`). No reorder exists to port.
- **Unused `AddCategoryDialog` (unverified):** `apps/frontend/src/features/categories/AddCategoryDialog.tsx` is not rendered by any page; only its test imports it. It may be dead code. [[docs/features/categories|Categories]], under "Frontend Reorganization", says `CategoriesPage` imports it. That is a doc/code conflict: the page uses `CategoryNodeDialog`.
- **Detail card and tax wrapper (unverified):** [[docs/features/accounts|Accounts]] lists "tax wrapper" in the Details card. The code deliberately omits it (`apps/frontend/src/pages/AccountDetailPage.tsx:372`). Doc/code conflict.
- **Archive/Restore menu items (unverified):** the accounts doc lists separate _Archive/Restore_ header-menu items. The code has only Close (while active) or Reopen (while closed) (`apps/frontend/src/pages/AccountDetailPage.tsx:466`). Doc/code conflict.
- **Planned transactions filter (unverified):** the accounts doc says upcoming planned rows are filtered by the account's canonical `name`. The frontend sends `account_id` (`apps/frontend/src/hooks/useAccountPlannedTransactions.ts:14`). The backend mapping was not checked.
- **Read-only payee rows (unverified):** [[docs/features/recipients|Recipients]] says repeated Active badges and empty Notes values are not shown in read-only rows. The code renders an Active or Inactive badge on every row (`apps/frontend/src/pages/RecipientsPage.tsx:451`) and "—" for empty notes (`apps/frontend/src/pages/RecipientsPage.tsx:443`). Doc/code conflict, unless `VirtualDataTable` hides them.
- **Payee search placeholder (unverified):** the `recipientsPage.search` key ("Search payees…") is defined but unused. The payees search box shows the generic `table.searchDatabase` ("Search…"), because `RecipientsPage` passes no placeholder (`apps/frontend/src/pages/RecipientsPage.tsx:674`).
- **Payee column filters (unverified):** in server mode, `VirtualDataTable` column filters apply only to rows already loaded, on the client (`apps/frontend/src/components/shared/VirtualDataTable.tsx:1484`). Whether this partial filtering is intended for payees was not confirmed.
- **Ledger error retry (unverified):** the ledger error state on `/accounts/:id` has no Retry button, because `PageError` gets no `onRetry` (`apps/frontend/src/pages/AccountDetailPage.tsx:829`). Whether this is intended was not confirmed.
- **Tag string interpolation (unverified):** `tags.create` and `tags.slugifyHint` use `{{slug}}` placeholders, which are substituted with `String.replace` instead of the i18n interpolator (`apps/frontend/src/components/shared/TagInput.tsx:225`, `:252`). A native port must take care with this copy.
- **Broker transfer ownership (unverified):** `BrokerTransferDialog` and `PortfolioLotRetagChoice` belong to the portfolio feature. They are listed here only because they are reachable from `/accounts/:id` and from Close account. The portfolio inventory should own their details.
- **Recipient insights (unverified):** Recipient Insights live in the Statistics page tab (`apps/frontend/src/features/statistics/RecipientInsightsTab.tsx`), which is out of scope here. They were not inventoried.
- **Merge payees lists (unverified):** the primary list in Merge payees excludes existing aliases, but the alias list includes them, labelled `merge.aliasOf` (`apps/frontend/src/features/recipients/MergeRecipientsDialog.tsx:247`). The server behavior when an alias is re-merged was not checked.
