# Native parity inventory: Analysis workspace and monitors

> [!abstract] Scope
> Routes: `/analysis`, `/analysis/monitors`. Source: `apps/frontend/src/pages/AnalysisWorkspacePage.tsx`, `apps/frontend/src/pages/AnalysisMonitorsPage.tsx`, `apps/frontend/src/features/analysis/`. Part of [[docs/reference/native-parity/index|the native parity inventory]] for [[docs/adr/204-vision-native-swift-app-target|ADR-204]].

Both routes are separate pages in the route manifest (`apps/frontend/src/lib/routePreload.ts:35`, `apps/frontend/src/lib/routePreload.ts:40`). Monitors is not a tab or query parameter of `/analysis`: it is its own sidebar entry `nav.analysisMonitors` "Analysis monitors" (`apps/frontend/src/lib/navigation.ts:247`) with an unread badge, next to `nav.analysisWorkspace` "Analysis workspace" (`apps/frontend/src/lib/navigation.ts:241`). The Analysis page has no link to Monitors. The Monitors page links back to `/analysis` only from its empty-target state.

## Screens

### `/analysis` — Analysis workspace

Component: `apps/frontend/src/pages/AnalysisWorkspacePage.tsx`. Feature docs: [[docs/features/analysis-workspace|Analysis Workspace]], [[docs/reference/analysis-contract|Analysis Contract Reference]], [[docs/reference/analysis-datasets|Analysis Datasets]].

**Native implementation (phase 3k):** `apps/native/Sources/VisionNativeUI/AnalysisWorkspaceView.swift` composes the query controls, peer result/interchange/workbench panels and reusable-analysis sidebar. Implemented controls are marked native below. The Mac/Demo gate remains open for EN/NL layout, focus, disclosure keyboard behavior, run/cancel, last-result preservation, saved-version/proposal dialogs, backend error states and the chart layouts. A native row records code coverage rather than a rendered or screenshot verification.

The page runs top to bottom as: header, workflow nav, optional financial-parameters card, template chooser, **Data** card (Run, Edit configuration with visual builder or SQL editor), **Present** card (Table/Chart/Pivot tabs), Contributing records card, **Refine this analysis** disclosure (Prepare and Calculate workbench), then an aside with the **Reusable analysis** (save) card and the **Saved analyses** library.

**URL state:**

- `?savedAnalysis=<id>` is read once on mount from `window.location.search` (not `useSearchParams`); when the saved list contains that id, it is loaded as if opened from the library (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:505`, `apps/frontend/src/pages/AnalysisWorkspacePage.tsx:1114`). It is produced by the AI investigation panel's `aiResearch.openAnalysis` link (`apps/frontend/src/features/ai-chat/AIInvestigationPanel.tsx:127`). The page never writes the URL.
- In-page anchors `#analysis-data`, `#analysis-prepare`, `#analysis-calculate`, `#analysis-present` (workflow nav).
- `localStorage` key `vision.analysis.sqlHistory` (`LOCAL_STORAGE_KEYS.ANALYSIS_SQL_HISTORY`) keeps up to ten custom SQL queries (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:531`, `apps/frontend/src/pages/AnalysisWorkspacePage.tsx:723`).

## Cross-cutting notes

- **No Electron bridge.** Neither page calls `window.electronAPI`. Exports use `downloadBlob` (anchor download of an in-memory Blob) (`apps/frontend/src/lib/downloadBlob.ts:8`); imports use hidden `<input type="file">`. A native app needs save/open panels for `.xlsx` and `.csv`.
- **Endpoints used by `/analysis`** (`apps/frontend/src/lib/api/analysis.ts`): `GET /api/analysis/catalog`, `POST /api/analysis/execute`, `POST /api/analysis/cancel/{requestId}`, `POST /api/analysis/drill`, `POST /api/analysis/pivot`, `POST /api/analysis/extensions/evaluate` (preview, prepare, time, formulas, scenarios, sensitivity, goal), `GET /api/analysis/saved?workspace=`, `POST /api/analysis/saved`, `PUT` and `DELETE /api/analysis/saved/{id}`, `POST /api/analysis/saved/{id}/run`, `GET /api/analysis/saved/{id}/versions`, `POST /api/analysis/saved/{id}/restore`, `POST /api/analysis/saved/{id}/ai-proposal`, `POST /api/analysis/ai-proposals/preview`, `POST /api/analysis/ai-proposals/apply`.
- **Endpoints used by `/analysis/monitors`** (`apps/frontend/src/lib/api/monitors.ts:112`): `GET/POST /api/analysis/monitors`, `PATCH/DELETE /api/analysis/monitors/{id}`, `POST /api/analysis/monitors/{id}/check`, `GET /api/analysis/monitors/{id}/observations`, `GET /api/analysis/monitors/notifications`, `POST /api/analysis/monitors/notifications/{id}/read`; plus `GET /api/analysis/saved` (all workspaces) and the dossier list for targets (`apps/frontend/src/hooks/useMonitors.ts:31`).
- **Stale-result guards** a native port must keep: query signature (`queryOutdated`) and transformation signature (`transformationsOutdated`) drive the outdated warning and export blocking (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:1139`); draft epoch and snapshot prevent late saved-operation responses from overwriting a newer draft (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:599`); run request id discards superseded runs (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:742`); the workbench ignores responses whose inputs changed (`apps/frontend/src/features/analysis/AnalysisWorkbenchPanel.tsx:352`).
- **Focus management:** template selection focuses Edit configuration; a successful explicit Run focuses and scrolls to the Present heading (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:732`); Add formula focuses the new expression input (`apps/frontend/src/features/analysis/AnalysisWorkbenchPanel.tsx:197`).
- **Shared components:** `RowMenu` (••• button with `aria-label`, `apps/frontend/src/components/shared/RowMenu.tsx`), `ListRow` (`apps/frontend/src/components/ui/list.tsx`), `useConfirmDialog`, `Disclosure`, `SegmentedControl`. The visual-plan filter, column, and dataset labels are localized via `analysisCatalogLabel` (`analysis.catalog.*` keys) while identifiers stay unchanged in queries and exports.
- **Persistence of non-saved state:** the run-preferences overrides, workbench, scenario model, chart spec and pivot config are page state only until Save; only SQL history persists locally.

- `docs/reference/frontend-routes.md` now lists both Analysis routes and their phase-3k native implementations; the earlier missing Monitors row is resolved.
- Pivot doc says "Column depth controls the visible column hierarchy", but code fixes `rowDepth`/`columnDepth` to `min(1, n)` with no control; keys `analysis.ext.pivot.rowDepth` and `analysis.ext.pivot.columnDepth` exist in `en.json` but are unused (`apps/frontend/src/features/analysis/AnalysisPivotPanel.tsx:70`). Deeper levels are reached only via expand buttons. Unverified whether a depth control was removed intentionally.
- `analysis.ext.pivot.expand` / `.collapse` use `{{field}}` while the translator replaces `{field}` (`apps/frontend/src/stores/hydration/LanguageHydration.tsx:226`); the aria label likely renders as "Expand {Food}" with literal braces. Unverified at runtime.
- `analysis.queryHistory` says "SQL history for this session", but history is persisted in `localStorage` across sessions (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:723`). Copy/behaviour conflict.
- Workbench hint `analysis.ext.workbench.attachmentRequired` says to import "in the Data section", but the import controls live in Reusable analysis › Export and scenario files. Copy conflict.
- Scenario CSV and workbook parse errors are hard-coded English strings (`apps/frontend/src/features/analysis/analysisInterchange.ts:79`, `apps/frontend/src/features/analysis/analysisWorkbook.ts:259`), not localized; Dutch users see English. Unverified whether intended.
- The feature doc says the saved library "is filtered by Budgeting, Portfolio, Research, or explicit cross-workspace scope"; there is no filter on the library card itself. The filter is the Workspace select inside Edit configuration (row 18), which a native design may want to surface. Unverified intent.
- Monitor field selects show raw column ids rather than localized labels (`apps/frontend/src/pages/AnalysisMonitorsPage.tsx:832`). Possibly intentional.
- `/api/analysis/formulas/evaluate` exists in the generated API types but is not called from either screen (`apps/frontend/src/types/generated.ts:172`). Unverified whether another surface uses it.
- The `?savedAnalysis=` deep link is applied only if the id is in the current workspace's saved list (default Budgeting), so links to analyses in other workspaces may not open (`apps/frontend/src/pages/AnalysisWorkspacePage.tsx:1114`). Unverified at runtime.
- Line references for multi-line JSX point to the handler line or the line carrying the label key; region references point to the opening element or its first label line. Unverified to the exact element start in every case.
