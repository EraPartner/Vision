# Architecture Decision Records

> [!abstract] What is an ADR?
> An ADR (Architecture Decision Record) documents a significant architectural decision along with its context, consequences, and status. Use these to understand **why** the system is built the way it is.

## Creating a New ADR

See [[docs/adr/template\|the ADR template]] for the format to use when creating a new decision record.

> [!tip] When to Create an ADR
> - Choosing a new technology or framework
> - Changing a fundamental architectural pattern
> - Documenting a significant bug fix with architectural implications
> - Recording a decision that affects multiple parts of the system

### 2026-06-16: Research Analytics & Forecasting Expansion (Pillars B/C/D Deepening)

[[docs/adr/081-research-analytics-forecasting|ADR-081]] — Supersedes the *Deferred* designation of Pillar C from ADR-079. **Pillar C (portfolio forecast) ships** via a Monte Carlo projection engine decoupling RISK (estimated from aggregate portfolio NAV daily-return history via `portfolioPerformanceSnapshotService` — embedded cross-holding covariance, no matrix required) from DRIFT (per-holding weighted blend of historical mean and forward-looking analyst inputs — 12m target-implied growth + dividend yield from `researchAggregator`, top-25 holdings by weight, capped ±50%, controlled by `forwardBlend` ∈ [0,1]). Two simulation methods: `parametric` (Gaussian monthly steps) and `block_bootstrap` (stationary Politis–Romano resample of de-meaned daily residuals). Reuses seeded PRNG from `services/calculations/forecast/prng.js` — deterministic per seed. Output: P10/P25/P50/P75/P90 bands per month + summary (expectedAnnualReturn, annualVolatility, probBelowInvested, probTarget) + forward-input provenance. Non-persisted (`POST /api/research/portfolio-forecast`). **Pillar B deepened** with freeform Chart Builder (`/research/charts`): multi-symbol, dual-axis, candlestick/line/area, SMA/EMA/Bollinger/RSI/MACD (client-side, `lib/research/indicators.ts`, zero extra quota), log scale, rebase, presets, localStorage layout. Chart endpoint gains optional `provider` param. **Pillar D deepened**: heuristic scorecard engine (`fundamentalsScorecard.js`) — `scoreFundamentals(f)` → score 0–100, grade A–F, per-metric flags (metric/category/severity ok|caution|warn|risk/code/reason/benchmark); missing fields skipped not penalized; thresholds are hardcoded heuristics, not ML. Extended fundamentals normalization across Yahoo (assetProfile module), Finnhub (metric=all), FMP (key-metrics-ttm + financial-growth) adds: sector, pegRatio, payoutRatio, grossMargin, operatingMargin, revenueGrowth, earningsGrowth, debtToEquity, currentRatio, quickRatio, interestCoverage, freeCashFlow, fcfYield. Scorecard UI: `ResearchScorecard.tsx`; Fundamentals tab redesigned; Compare page Health column. `openapi.yaml`: 192 operations total. Known gap: scorecard `reason` strings are English-only (tracked follow-up).

### 2026-06-16: Layered Backend Env Loading with a Shared Root Secrets Base

[[docs/adr/080-layered-env-loading-shared-secrets|ADR-080]] — `loadDotenv.js` now layers two files: `apps/node-backend/.env.local` (local-dev overrides — localhost DB URL, CORS, ports) applied first, then the repo-root `.env` (shared secrets base — provider API keys, the same file Docker reads via `env_file: .env`). Precedence: real `process.env` > dev-local > root `.env`. This lets **context-independent secrets like the ADR-079 provider API keys live ONCE in root `.env`** for both dev and Docker (no more dev-vs-Docker duplication), while context-specific DB/host config stays per-context. The **stray root `.env.local`** — which no loader read — is retired (templates + docs no longer reference it; it's gitignored, so existing clones move any values into root `.env` and delete it). Docker behavior is unchanged (compose injects root `.env` before the loader runs; the dev-local file is absent in the image). Caveat: a dev run relies on its `.env.local` defining `DATABASE_URL`, else the root `.env`'s Docker DB URL leaks into dev — the template ships the override.

### 2026-06-16: Multi-Provider Research Data Aggregation with Cross-Provider Symbol Mapping

> [!note] Pillar C deferred designation superseded by ADR-081 (2026-06-16)
> The *Deferred* status of Pillar C (portfolio projection) recorded in this ADR has been superseded by [[docs/adr/081-research-analytics-forecasting|ADR-081]], which ships Pillar C. All other items remain current.

[[docs/adr/079-multi-provider-research-aggregation|ADR-079]] — A new **Research section** (pillars A workspace, B comparative analysis, D screening; C portfolio projection initially deferred as orthogonal — superseded by ADR-081) aggregates **five** market-data providers — Yahoo (existing), Twelve Data, Finnhub, FMP, Alpha Vantage — behind the existing `priceProviderRegistry`. No single free tier beats Yahoo on breadth, but their **union** does, if routed to avoid rate limits. **Three new layers**: (1) a static **capability map** `(dataType, assetClass) → ordered provider preference`; (2) a **quota governor** of per-provider token buckets (per-minute in-memory + **per-day persisted** in a new `provider_quota` table, since restarts would otherwise blow daily caps like Alpha Vantage's ~25/day), checked via `canSpend()` before every call with fall-through to the next provider on exhaustion; (3) **type-aware cache TTLs** (quotes 5–15 min, charts/history 12–24 h, fundamentals 24 h+, news 1–4 h) as the primary rate-limit defence. Field-merge is **lazy per research tab** (overview = 1 quote call; Fundamentals tab = 1 FMP call cached 24 h; News tab = 1 Finnhub call) — eager merging would drain quotas. **Storage stays narrow**: research data for arbitrary symbols is fetched live and cached in memory only — **never** written to `asset_price_history`; the held-asset holding-window persistence of ADR-065 is untouched. The correctness anchor is a **user-confirmed cross-provider symbol map** (`instrument_provider_map` table): provider searches **auto-propose** a best guess, the user **confirms the resolved instrument** (name + exchange + currency shown, so ticker collisions like `APLE` vs `AAPL` are caught), mappings are **anchored on ISIN** where available (internal id for crypto/metals), **pre-seeded from holdings**, **degrade visibly when unmapped**, and **self-audit** via cross-provider currency/price agreement. Reuses `providerHealthService` (ADR-034) for unhealthy-provider skip. Providers with no `.env.local` key are dropped from preference lists (Yahoo needs none). Honest limits: N adapters/keys/ToS to maintain, symbol identity carries the main correctness risk, free-tier churn, and screening (D) never fully arrives on free tiers (EU fundamentals depth needs a paid source like EODHD).

### 2026-06-11: FX Attribution with Purchase-Date Rates

[[docs/adr/074-fx-attribution-historical-rates|ADR-074]] — Closes a three-part defect in multi-currency portfolios: (1) invested capital was restated at today's FX on every load; (2) no decomposition of gain into asset vs. currency components; (3) historical rates before the 90-day ECB feed were fabricated from nearest-known values. Decision: *flows* (buys, sells, fees, taxes, income) convert at their **transaction-date** rate; *holdings values* convert at today's rate. `gainLoss = assetGain + fxGain` by construction, per-investment and in totals. The shared cost-basis calculators (`@vision/shared-utils/portfolio`, ADR-073) carry a parallel **converted track** (`fxMultiplier` per txn + `fxMultiplierNow`). `rateFetcher` gains an ECB **full-history** tier (`eurofxref-hist.xml`, daily since 1999, 24h-cached) with on-or-before weekend convention. Startup backfill: one-time repairs of fabricated rows (flagged via `user_settings.fx_full_history_repair_done`), fills missing (currency, date) pairs without guessing, bulk-stamps `fx_rate_to_eur` on non-EUR transactions (≤7-day lookback). New/edited transactions stamped from stored rates at write time (DB-only). `portfolio_performance_snapshots` gains nullable `value_fx_neutral` (migration 0039): portfolio at cost-weighted purchase-date rates; the FX-neutral chart series is absent until migrated. API additions (non-breaking): per-investment `assetGain`, `fxGain`, `nativeCurrentValue`, `usedFallbackRate`; totals `totalAssetGain`, `totalFxGain`, `usedFallbackRate`; snapshots `value_fx_neutral?`.

### 2026-04-21: Express 5 Compatibility: path-to-regexp Override

### 2026-04-21: Alembic as Single Source of Schema Truth

[[docs/adr/027-alembic-single-source-of-schema|ADR-027]] — Delete `apps/node-backend/src/database/schemaInit.js` (1021 LOC, idempotent CREATE-IF-NOT-EXISTS) and make Alembic the sole owner of schema DDL. Node-backend boot shells out to `alembic upgrade head` via `child_process.execFile`; fails fast on non-zero exit. `schema_version` table removed — Alembic's `alembic_version` replaces it. `stampBaselineIfLegacy()` pre-upgrade hook rewrites pre-ADR-027 DBs (stamped at legacy revisions 0002–0032 in `alembic/legacy_versions/`) to `0001_initial` baseline without running DDL. Diff schemaInit output vs alembic head → back-fill missing objects as new revisions (expected 3–6). Enables real `downgrade()` support for Phase 5+ feature migrations. Electron packaging gains runtime dependency on bundled Python + alembic.

### 2026-04-20: Unified API Response Envelope

[[docs/adr/026-unified-api-response-envelope|ADR-026]] — All 108 HTTP endpoints return a discriminated union envelope keyed on `ok`: `{ ok: true, data, meta? }` on 2xx / `{ ok: false, error: { code, message, details? } }` on 4xx/5xx. Extends ADR-011's aggregation envelope to every route. New `wrapResponse` middleware exposes `res.ok(data, meta?)`; `createErrorHandler` rewritten to emit the failure shape. Frontend `api.ts` unwraps once and throws typed `ApiClientError`. Stable `ApiErrorCode` enum enables UI branching and i18n message keys. Request IDs propagate via `meta.requestId` for cross-log correlation. Breaking change rolled in one phase with no coexistence window; reversible entirely in code.

### 2026-04-20: Theme Variant System

[[docs/adr/025-theme-variant-system|ADR-025]] — Per-user theme variant selection with five curated color palettes (default, dracula, solarized, nord, high-contrast), each with light and dark sub-palettes. Backend validation enforces variant ∈ {default,dracula,solarized,nord,high-contrast}, mode ∈ {light,dark,system,schedule}, and schedule times (if applicable) match HH:MM. ### 2026-04-19: Update Installer Checksum Verification

### 2026-04-19: Electron Sandbox Hardening and Recovery

[[docs/adr/022-electron-sandbox-hardening-and-recovery|ADR-022]] — Enable renderer sandbox (`sandbox: true`) for defense-in-depth isolation. Add single-instance lock to prevent multiple app instances. Implement backend health-polling at startup (200 attempts, 60s timeout) and 10-second watchdog after startup; 3 consecutive failures emit `backend:lost` IPC event. Error page shows on startup timeout; recovery buttons trigger `recovery:retry` IPC or open logs. Corrupt `settings.json` is quarantined with timestamp suffix instead of silently failing. Env vars: `VISION_HEALTH_POLL_ATTEMPTS`, `VISION_HEALTH_POLL_INTERVAL_MS`. New i18n keys: `app.errorPageTitle`, `app.errorPageMessage`, `app.errorPageRetry`, `app.errorPageOpenLogs`, `app.backendLost`.

### 2026-04-19: Decimal Arithmetic for Monetary Values

[[docs/adr/021-decimal-arithmetic-for-monetary-values|ADR-021]] — Adopt Decimal.js for all monetary calculations to eliminate floating-point drift. IEEE 754 floating-point cannot exactly represent decimal values (0.1 + 0.2 ≠ 0.3 in JavaScript). New `money.js` module exports `toDecimal`, `addAll`, `subtract`, `roundToCents`, `toNumber` functions. Banker's rounding (HALF_EVEN, 2 DP) matches PostgreSQL NUMERIC semantics. Scoped to split/aggregation hotspots in Phase 9; exportable to frontend in Phase 10+.
