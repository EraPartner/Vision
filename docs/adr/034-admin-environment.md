# ADR-034: Admin Environment — Unified Observability Hub

## Status

Accepted

## Date

2026-04-24

## Context

Vision had scattered admin tooling: the DB Maintenance page lived under the "Data" sidebar group, provider-health backends had no UI, and endpoint liveness was invisible. There was no single place to confirm the platform is working correctly.

The user wanted an admin section that:
- Surfaces DB maintenance, data-source health, and endpoint liveness in one place
- Is hidden by default to avoid cluttering the sidebar for normal use
- Works for a single-user self-hosted app, so gating is ergonomic (hide clutter), not a security boundary

## Decision

**Gating:** A `adminMode: boolean` field was added to `AppSettings` (Zustand store + persisted via `apiClient.saveSetting`). A "Developer" section in the App settings tab exposes a toggle. No route guards — routes remain URL-accessible; toggle is ergonomic only.

**Placement:** A new "Admin" `SidebarGroup` is rendered only when `adminMode === true`. Existing DB Maintenance entry was moved from "Data" into Admin. Shadow divergences were excluded — that feature was removed via migration 0009.

**Health model:** Provider health uses a passive approach (existing services call `recordSuccess`/`recordError` on every operation, stored in `provider_health` table) plus an active on-demand "Check now" probe per row.

**Liveness metrics:** In-memory rolling window (15-minute, 1-minute buckets) via `requestMetrics` middleware. Metrics reset on restart — this is acceptable for a single-user app where restarts are infrequent.

**Alert surface:** Admin pages only. No global toasts, badges, or notification dots for admin-level failures.

**Scope:**
- `/admin` — Overview dashboard with 3 summary tiles
- `/admin/db` — Existing DB Maintenance page (moved)
- `/admin/providers` — Data Sources health (7 providers: Binance, Yahoo, Kinesis, ECB, open.er-api, Statbel, Eurostat)
- `/admin/endpoints` — Route liveness matrix (manifest + rolling metrics)

## Consequences

**Positive:**
- All operational visibility in one place
- Zero infrastructure overhead (no external monitoring, no webhooks)
- Provider health persists across restarts (DB-backed)
- Endpoint metrics are real, not synthetic — based on actual request traffic

**Negative:**
- Endpoint metrics reset on backend restart (in-memory)
- Provider health depends on regular traffic — a provider that is never polled shows "never"
- Admin mode is client-side only; a determined user can access `/admin/*` routes even with toggle off

**Neutral:**
- The `label` field in `provider_health` is set at probe/record time from a static map in `providerHealthService.js`
- Endpoint manifest is generated by scanning Express router stack at startup via `routeManifest.js`
